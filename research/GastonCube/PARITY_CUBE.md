# 汇报中的偶校验 Cube：三次求和与 MILP 单项式预测

本实现对应 [Gaston 六轮 Cube 分析汇报](/home/yxb/分析/Cube/汇报_Gaston六轮Cube分析_截图版.md) 中的旋转不变偶校验 Cube。程序为 `gaston_parity_cube.cpp`，与处理原始独立坐标的 `gaston_cube.cpp` 分开，两者共用 `gaston_mp.hpp` 中的精确单项式预测引擎。

## 1. 精确研究对象

初始化输入为

\[
S^{(0)}=(\mathtt{0x00001000808c0001},K_0,K_1,N_0,N_1),
\]

采用 Gaston 最后六个轮常量，观察输出 `S0,S1`。在空关联数据、首块明文为零的约定下，它们就是首个密文块。输出位 `0..63` 属于 `S0`，`64..127` 属于 `S1`；密钥位按同样方式对应 `K0,K1`，字内 bit 0 为最低位。

本次 Cube 为

\[
U=\{(N_0,0):\ \bigoplus_{j=0}^{63}N_0[j]=0\}.
\]

使用 63 个独立变量参数化：

\[
N_0[0]=u_1+\cdots+u_{63},\qquad N_0[j]=u_j\quad(1\le j\le63),\qquad N_1=0.
\]

其基为 \(e_0+e_j\)，\(1\le j\le63\)。这是一个线性子空间 Cube，不是“固定某个 nonce 位为零”的坐标 Cube，也不是此前选出的 `0,2,...,124` 坐标集合。配置和 63 个基方向见 `parity_cube_config.json`。

程序将上述线性形式直接代入多项式电路：只有 63 个独立的 \(u_j\) 源，`N0[0]` 是它们的 SUM 节点。**不能先把 64 个 nonce 位当成独立单项式源，再用输入值的偶校验约束代替这个代入**。单项式传播处理的是多项式展开关系。

## 2. 三次完整 Cube 求和的含义

设

\[
S_U(K)=\bigoplus_{u\in\mathbb F_2^{63}}F^{(6)}(K,N(u)).
\]

线性参数化不增加次数，六轮总次数至多为 64，因此

\[
S_U(K)=c+AK,\qquad A\in\mathbb F_2^{128\times128}.
\]

\(A\) 的元素是 \([k_i u_1\cdots u_{63}]F_j^{(6)}\)。它的总次数已达 64，故与固定 IV、轮常数无关。\(c\) 可能依赖这些常数。

Cube 在同时循环旋转各字的作用下不变；去掉常数对最高次系数的影响后，Gaston 的线性层和最高次非线性部分也与旋转交换。因此输入、输出的字内旋转满足

\[
A R_j=R_j A.
\]

在真实 IV、轮常数下计算

\[
s_0=S_U(0),\quad s_1=S_U(e_{0,0}),\quad s_2=S_U(e_{1,0}),
\]

即可得到

\[
c=s_0,\qquad v_0=s_1+s_0,\qquad v_1=s_2+s_0,
\qquad A e_{a,j}=R_jv_a.
\]

这里每次求和覆盖完整的 \(2^{63}\) 个点；三次共 \(3\cdot2^{63}\) 次六轮计算。“三次”描述的是完整 Cube 求和次数，不是三次置换运算，也不是三次 MILP 求解。旋转分别作用于两个输出字，不能跨越字边界旋转 128 位串。

`src/three_cube_reference.py` 实现这个直接求和方案，包含 IV、轮常数及 χ 的全部低次项，主要用于小轮独立验证。

## 3. MILP 直接计算最高次密钥系数

MILP 路线直接计算 \(A\)，不先求 \(s_0,s_1,s_2\)。只需最终的 \(k_i u_1\cdots u_{63}\) 系数，故第 \(t\) 轮只保留总次数为 \(2^t\) 的齐次层，并分别维护

\[
P^{(t)}:\ (\deg_k,\deg_u)=(0,2^t),\qquad
Q^{(t)}:\ (\deg_k,\deg_u)=(1,2^t-1).
\]

初始分量为

\[
P^{(0)}=(0,0,0,N_0(u),0),\qquad Q^{(0)}=(0,K_0,K_1,0,0).
\]

令 \(p=L(P^{(t)})\)、\(q=L(Q^{(t)})\)。对每一列，行下标按模 5 计算：

\[
P_i^{(t+1)}=p_{i+1}p_{i+2},\qquad
Q_i^{(t+1)}=p_{i+1}q_{i+2}+q_{i+1}p_{i+2}.
\]

程序不构造两个密钥分量相乘的项。最终只提取 \(Q^{(6)}\)；因只有 63 个独立 \(u\) 变量，\(P^{(6)}=0\)。

精确性来自最高次关联分次代数

\[
\mathbb F_2[k,u]/(k_i^2,u_j^2).
\]

重复变量使乘积的最高次部分为零；不重复的乘积中，密钥次数相加，不能从至少 2 次降到 1 次。这个截断仅适用于总次数达到上界的目标，不能直接用来计算常数项 \(c\) 的 63 次系数。完整布尔环中的 \(k_i^2=k_i\) 并不允许一般性地丢掉所有高密钥次数中间项。

第一轮二次式完整展开并按 GF(2) 抵消；其余轮用共享 SUM/PRODUCT 有向无环电路表示。

## 4. MILP 约束与系数认证

为电路节点引入二进制活动变量 \(a_v\)，为 SUM 分支引入二进制变量 \(e_{v,w}\)。

1. SUM 节点满足 \(\sum_w e_{v,w}=a_v\)，表示选择一个多项式加数。这不是状态值的 XOR 方程。
2. PRODUCT 节点活动时，必须使用全部因子。
3. 每个节点满足“自身活动量 = 根节点需求 + 所有使用它的边的需求”。活动量的二进制上界排除重复使用正次数子表达式。
4. 63 个独立 \(u_j\) 源全部活动；密钥源恰好有一个活动。

节点重复使用的删除也保持奇偶性：在该最高次代数中，任意正次数元素 \(P\) 满足 \(P^2=0\)，相关贡献可以整体抵消。模型记录的是经过这些精确局部抵消后的贡献路径。

`--key all` 把全部 128 个密钥作为候选源，对每条可行路径记录其唯一密钥。完整路径数按密钥分别取模 2，得到一个输出位的全部一次密钥系数。

- `build`：仅构造模型，通常不产生系数证书；若符号表达式已精确为零，可直接认证零。
- `screen`：不可行可证明目标系数全部为零；可行只证明贡献路径存在。
- `count`：使用 `PoolSearchMode=2` 分批完整枚举，逐批加入 no-good 排除已计数路径。只有全部穷尽才认证系数。

系数未知时保存为 `null`。**一条可行路径、奇数条已见路径、尚未完成的解池，都不是系数为 1 的证书**。

## 5. 利用旋转，计算两个代表输出行

直接按汇报的两列思路，需要求两个代表密钥 \(k_0,k_{64}\) 在 128 个输出位上的系数，共 256 个标量。新程序支持逐项计算；矩阵脚本采用等价的两个代表行方式，每个行任务联合枚举全部密钥源。

定义

\[
r_b[a,j]=A_{64b,\,64a+j},\qquad a,b\in\{0,1\}.
\]

由分块循环结构，所有矩阵元素满足

\[
\boxed{A_{64b+t,\,64a+j}=r_b[a,(j-t)\bmod64].}
\]

两个代表列则为

\[
\boxed{v_a[64b+t]=r_b[a,(-t)\bmod64].}
\]

因此只需要完成输出位 `0` 和 `64` 的两个联合系数任务。每个任务仍可能包含多轮求解和大量路径；没有关于六轮完整运行时间的保证。若只完成一个代表行，则对应的 64 个输出行可认证，另一半保持未知，程序不对不完整矩阵报告精确秩。

## 6. 编译与使用

```bash
cd /home/yxb/分析/GastonCube
make gaston_parity_cube
```

依赖 C++17 与 Gurobi，默认 `/opt/gurobi1302/linux64`。保持完整控制台日志，不设置求解时间上限；Ctrl+C 请求结束求解并保存已经提取的路径。`make SRC=gaston_parity_cube.cpp` 同样可用。

构造六轮的两个代表行模型：

```bash
python3 src/run_parity_matrix.py --mode build
```

开始完整路径奇偶性计算：

```bash
python3 src/run_parity_matrix.py --mode count
```

结果位于 `results/parity/r6_w64_split1_count/`：`row_0.json`、`row_1.json` 是代表行状态，`.trails` 文件用于接续，`matrix.json` 保存代表行、代表列、完整矩阵、已认证系数为 1 的位置及完整时的秩。再次执行自动接续；不要同时运行两个进程写入同一任务的 checkpoint。

只处理第一个代表行，或只汇总已有结果：

```bash
python3 src/run_parity_matrix.py --output-words 0
python3 src/run_parity_matrix.py --summarize-only
```

直接计算某个代表列的单个系数：

```bash
./gaston_parity_cube --rounds 6 --key 0 --output-bit 0 \
  --mode count --result results/parity_k0_o0.json \
  --checkpoint results/parity_k0_o0.trails
```

该命令不接受 `--nonce`：输入方向由偶校验参数化固定。`--key 64` 选第二个代表密钥；`--key all` 同时恢复所选输出位的全部密钥系数。默认 `--key-split 1` 逐轮截断，`--key-split 0` 可比较旧式混合电路。不同电路的 checkpoint 不可混用。

直接三次 Cube 求和的小轮验证：

```bash
python3 src/three_cube_reference.py --rounds 3 \
  --result results/parity_three_cube_r3.json
```

小轮验证仍采用实际 64 位字长，第 \(r\) 轮对应周期 \(2^r\) 的偶校验块重复填满 `N0`，Cube 维数为 \(2^r-1\)。例如三轮使用 8 位偶校验块重复 8 次；六轮的周期为 64，恰好就是汇报中的 Cube。三轮示例每次求和 128 个点，三次共 384 次完整布尔计算。

## 7. 实测规模与结论范围

六轮、全部密钥、默认逐轮截断、第一轮展开的模型已经成功构建。以下是求解器预处理前的规模：

| 代表输出 | 二进制变量数 | 约束数 |
|---|---:|---:|
| `S0[0]` | 820364 | 17274 |
| `S1[0]` | 820447 | 17296 |

原始结果位于 `results/parity/r6_w64_split1_build/`。建模成功不代表六轮矩阵已求出。

`tests/validate_parity.py` 将单项式预测与独立完整布尔求和比较，检查 1–3 轮的全部密钥列旋转关系、随机密钥仿射关系、IV/轮常数改变后的系数不变性、MILP 系数、矩阵重建、接续和未知条目处理。验证状态以 `results/parity_validation_summary.json` 为准。

当前验证全部通过：384 个独立完整求和的密钥列、9 个随机密钥仿射关系、12 次 IV/轮常数变化后的系数核对、1030 个 MILP 系数比较，以及矩阵脚本、三次求和、接续和未知条目的检查。对应 1、2、3 轮周期偶校验 Cube 的完整布尔矩阵秩分别为 64、127、128；这些小轮结果不能代替六轮结论。

**六轮的实际系数矩阵、精确秩与常数项仍未完成计算**。最高次 MILP 路线只负责 \(A\)，结果中的 `constant_term:null` 不能解释为零。若需要完整 \(c+AK\)，还需零密钥完整 Cube 求和或另一个覆盖相关低次项的精确算法。汇报中“秩约为 125”的工作假设没有写入求解器或结果。


## 逐密钥搜索（2026-10-31）

驱动脚本现在默认逐个求解 k0、k1、…、k127。每个密钥先求 S0[0]，再求 S1[0]。目标密钥保持符号变量，其余密钥输入在电路构造前置零；仍只提取一次密钥、63 次 Cube 参数的项。

```bash
# 顺序处理所有密钥，从 k0 开始；重复执行自动接续
python3 src/run_parity_matrix.py --mode count
# 仅处理 k0 的两个代表输出位
python3 src/run_parity_matrix.py --mode count --keys 0
# 仅处理 k0、k1
python3 src/run_parity_matrix.py --mode count --keys 0,1
# 旧的联合模型及其原断点
python3 src/run_parity_matrix.py --mode count --keys joint
```

逐密钥结果默认写入 `results/parity/r6_w64_split1_count_individual/`，例如 `key_0_row_0.json` 和 `key_0_row_0.trails`。旧联合断点保留在原目录，不能直接作为单密钥模型的断点。每个完成的系数经旋转关系补充矩阵；未完成的系数仍为 null，只有完整矩阵才报告秩。单密钥的已枚举路径仍须全部计数取奇偶，找到一条路径不能认证系数为 1。
